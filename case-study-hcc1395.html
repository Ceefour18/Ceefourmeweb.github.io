HCC1395 Somatic WGS Pipeline

End-to-end tumour–normal whole-genome sequencing pipeline for breast cancer, benchmarked against the SEQC2 gold-standard truth set — from raw FASTQ through Mutect2 calling, debugging and validation.

Problem

Clinical genomics teams need somatic variant calling pipelines that are reproducible and validated against community gold standards — not just "it runs." The SEQC2 consortium established HCC1395 (triple-negative breast cancer) and HCC1395BL (matched normal) as reference samples with high-confidence somatic SNV/INDEL truth sets across ~40,000 SNVs and complex genomic alterations.

The goal: build a Docker-based WGS pipeline targeting clinically relevant breast cancer genes, validate calls against the SEQC2 v1.2 truth set, and document the full debugging process — the kind of work expected on industry precision oncology platforms.

Approach

A modular, bash-orchestrated pipeline deployed on AWS (r6i.4xlarge: 16 vCPU, 128 GB RAM, 500 GB gp3 storage), with each stage containerised for reproducibility:

  • Alignment — BWA-MEM on paired-end tumour/normal FASTQs with proper read groups
  • Pre-processing — GATK MarkDuplicates and BQSR against dbSNP138 + Mills indels
  • Calling — Mutect2 tumour–normal paired mode → FilterMutectCalls
  • Downstream — structural variant calling and SnpEff functional annotation
  • Validation — comparison against SEQC2 high-confidence regions; variant-level sensitivity/precision profiling

When local WSL2 compute became a bottleneck (~48 h end-to-end), I migrated the alignment and Mutect2 stages to Google Colab Pro+ with mounted Drive storage, cutting wall-clock runtime to ~14 h without changing the analytical logic.

Key challenge: FASTQ read-name mismatch

Debugging a silent alignment failure

BWA-MEM alignment initially produced BAMs with no properly paired reads. Inspecting the FASTQ headers revealed the cause: tumour R1 and R2 files used inconsistent read-name suffixes (/1 vs /2 mismatches, and truncated IDs between the SEQC2 SRA download and my local rename step). BWA needs strictly paired read names — a mismatch means a pipeline that "completes" but produces no callable variants.

Fix: a normalisation script that strips platform-specific suffixes and enforces consistent @READ_ID 1:N:0:… / @READ_ID 2:N:0:… naming across all four FASTQ files, followed by FastQC to confirm paired-end integrity before re-running alignment. That single fix unblocked the entire downstream Mutect2 chain.

Results

  • Somatic calls validated against the SEQC2 v1.2 high-confidence truth set (HCC1395/HCC1395BL) in benchmark regions
  • Full tumour–normal workflow automated from FASTQ to filtered VCF with reproducible Docker mounts
  • Runtime reduced ~3× (~48 h → ~14 h) by moving compute-heavy stages to Colab Pro+
  • The companion WES pipeline (HCC1143, chr17) independently recovered clonal TP53 p.Arg248Gln at 98.6% VAF with 1.11% cross-sample contamination

What I'd do next

  • Port the bash workflow to Nextflow following nf-core conventions for HPC and cloud scalability
  • Extend validation to the full-genome SEQC2 INDEL truth set and publish a comparison notebook
  • Integrate RNA-seq from the same cell line for multi-omics driver confirmation
  • Add CNV calling (GATK CNV or Control-FREEC) given HCC1395's known aneuploidy
  • Containerise with Singularity/Apptainer for institutional HPC deployment
